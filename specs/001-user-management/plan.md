# Implementation Plan: User Management Module

**Branch**: `001-user-management` | **Date**: 2026-06-08 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/001-user-management/spec.md`

## Summary

The User Management module establishes the authentication and account lifecycle
foundation for the mobile maintenance app. A pre-seeded Supervisor account is the sole
administrative user. Supervisors create Technician accounts (auto-assigned password
COLBO2026), view and edit the technician roster, and can disable accounts with immediate
session invalidation. Both roles authenticate with JWT tokens stored securely on the
device and persist across app restarts. Both roles can update their own display name and
password; Technicians cannot access management screens.

## Technical Context

**Language/Version**: Python 3.11 (backend), Dart 3.x / Flutter 3.x (mobile)

**Primary Dependencies**:
- Backend: FastAPI 0.111+, SQLAlchemy 2.0 (async), Alembic, python-jose[cryptography]
  (JWT), passlib[bcrypt] (password hashing), pydantic-settings
- Mobile: Riverpod 2.x (AsyncNotifier), flutter_secure_storage 9.x (JWT persistence),
  Dio 5.x (HTTP + auth interceptor), go_router 13.x

**Storage**: PostgreSQL 15 (Railway) — single source of truth; no local DB for this
module (internet required per spec assumption)

**Testing**:
- Backend: pytest + httpx (async test client), pytest-asyncio, factory_boy
- Mobile: flutter_test (unit + widget tests)

**Target Platform**: Railway Linux server (FastAPI + PostgreSQL); iOS 14+ / Android 8+

**Project Type**: mobile-app + REST API web-service

**Performance Goals**:
- Login response: < 2 s
- Technician list (200 accounts): loads within 3 s
- Account disable takes effect (blocks next API call): < 5 s

**Constraints**:
- Hexagonal architecture on backend: domain core isolated from FastAPI / SQLAlchemy
- MVVM + Riverpod on Flutter; BLoC/Cubit forbidden
- JWT stored in flutter_secure_storage (not shared preferences)
- Session invalidation for disabled accounts: enforced by FastAPI auth dependency
  checking user.status on every protected request
- All secrets (JWT secret key, default password hash seed) via environment variables
- Passwords hashed with bcrypt; minimum 6 characters enforced in domain layer
- Internet connection required for all actions; no offline auth

**Scale/Scope**: 1 Supervisor, up to 200 Technicians
